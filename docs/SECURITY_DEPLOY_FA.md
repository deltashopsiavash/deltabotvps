# راهنمای استقرار اصلاحات امنیتی

این اصلاحات توکن تلگرام، توکن Hetzner، اطلاعات مشتریان و کلید امضای اندروید را تغییر نمی‌دهند.

## پیش‌نیاز
- PHP CI برای همان commit باید موفق باشد.
- قبل از جایگزینی فایل‌ها، بکاپ امن سورس و دیتابیس تهیه شود.
- برای سرورهای پشت proxy، وب‌هوک مادر و نمایندگی‌های فعال باید Secret داشته باشند. کد جدید بدون Secret درخواست را رد می‌کند.

از یک checkout معتبر خارج از webroot، فایل scripts/configure-webhook-auth.php را روی سرور در مسیر پروژه قرار دهید. با اجرای CLI:

    php scripts/configure-webhook-auth.php --check

URLهای فعال بررسی می‌شوند. سپس:

    php scripts/configure-webhook-auth.php --apply

با همان توکن فعلی، Secret متناظر ثبت می‌شود. URL و آپدیت‌های منتظر حذف نمی‌شوند. اگر گواهی سفارشی استفاده شود، عملیات متوقف شده و به تنظیم دستی نیاز دارد. پس از ثبت، کارکرد ربات مادر و نمایندگی‌ها را بررسی کنید.

برای Apache روی نصب استاندارد /var/www/html/deltabotvps، فایل apache-delta-private.conf در همین پوشه را با نام delta-private.conf در /etc/apache2/conf-available نصب کنید. ابتدا a2enconf و apache2ctl configtest و سپس reload؛ در صورت خطا تنظیم جدید را غیرفعال کنید. این فایل برای Nginx مناسب نیست. اجرای PHP و دسترسی داخلی به فایل‌ها را تغییر نمی‌دهد.

رمزهای جدید و بازنشانی‌شده ۲۲ کاراکتر تصادفی هستند. رمزهای فعلی بدون درخواست کاربر تغییر نمی‌کنند. نشست‌های جدید حداکثر ۹۰ روز اعتبار دارند؛ نشست‌های قدیمی هنگام استقرار امنیتی به حداکثر ۹۰ روز از زمان استقرار محدود می‌شوند و در API نیز سقف اعتبار کنترل می‌شود. پس از انقضا ورود مجدد لازم است.

**پس از استقرار**: ورود معتبر و نامعتبر، خرید، پرداخت کیف پول و کارت، لغو، تمدید، تحویل سرویس، وب‌هوک مادر و نمایندگی، تأیید پیامکی و بازیابی را با حساب تست بررسی کنید. نسخه اندروید پس از Build و امضا و آزمون دستگاه واقعی منتشر می‌شود.

توجه: حذف فایل‌های محرمانه از شاخه اصلی، اعتبارنامه‌های قدیمی یا نسخه‌های موجود در تاریخچه را باطل نمی‌کند. اگر توکن‌های قبلی عوض نشوند، ریسک دسترسی غیرمجاز باقی می‌ماند. ریپوی فروش در صورت خصوصی شدن به احراز هویت GitHub برای اسکریپت‌های نصب و آپدیت نیاز دارد.

## استقرار هدفمند (بدون حذف پوشه فعلی)

از checkout کامل و بررسی‌شده خارج از webroot با GitHub CLI متصل:

    bash scripts/deploy-delta-security.sh --check COMMIT_SHA
    bash scripts/deploy-delta-security.sh --apply COMMIT_SHA

اجرای apply تنها پس از موفقیت CI برای همان commit، تطبیق فایل‌های نصب‌شده، آماده بودن وب‌هوک و تهیه بکاپ کد و دیتابیس مادر ادامه می‌یابد. این مسیر مهاجرت قدیمی و مخرب دیتابیس را اجرا نمی‌کند. نسخه‌های محلی متفاوت بدون بررسی جایگزین نمی‌شوند. بکاپ دیتابیس مادر شامل دیتابیس جداگانه نمایندگی‌ها نیست؛ قبل از استقرار از آن‌ها نیز بکاپ مستقل بگیرید. هیچ توکنی در خروجی نمایش داده نمی‌شود.
