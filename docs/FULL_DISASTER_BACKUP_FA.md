# بکاپ رمزگذاری‌شده کل مجموعه دلتا — نسخه توسعه

مخصوص VPS اختصاصی botme، Ubuntu 24.04 و دیتابیس مادر delta. پیش از انتشار روی سرور اصلی، CI و بازیابی واقعی روی VPS جداگانه الزامی است.

## بکاپ
- dump یکپارچه از delta، تمام دیتابیس‌های موجود delta_rbN و delta_sms_bridge، شامل ساختار و داده، رویه‌ها، رویدادها و triggerها.
- در صورت فقدان دیتابیس نمایندگی فعال بکاپ متوقف می‌شود. نمایندگی 71 حذف منطقی‌شده دوباره فعال نمی‌شود.
- وب‌روت اختصاصی، پنل و DeltaPay، Apache/PHP/MySQL، SSL، Cron، سورس عملیاتی، سرویس‌های VPSBot و تنظیمات و سوابق SMS Bridge.
- فایل SQLite واقعی در مسیرهای VPSBot با SQLite backup API ذخیره می‌شود؛ مسیرهای سفارشی خارج از محدوده باید جداگانه شناسایی شوند.
- AES256/GPG با رمز مستقل مالک، manifest و هش SHA-256 اجزا.
- فهرست بسته‌های نصب‌شده؛ محیط Python و وابستگی‌ها روی سرور جدید بازسازی می‌شوند.
- سیستم‌عامل، پنل‌های VPN خارجی، اطلاعات گوشی‌ها، کلید امضای APK در مخزن مستقل و فایل‌های خارج از محدوده بکاپ نیستند.

## نصب قابلیت روی ربات موجود
در checkout جداگانه و مطمئن با commit تأییدشده توسط CI:
```bash
sudo bash scripts/deploy-full-backup.sh EXACT_VERIFIED_COMMIT
```
این دستور فقط فایل‌های bot.php و backup_worker.php و helper محدود root را نصب می‌کند؛ قبل از نصب، نسخه فایل‌های زنده را با مبنا مقایسه و نسخه قبلی را حفظ می‌کند. توکن‌ها و webhookها تغییر نمی‌کنند. رمز مستقل حداقل 24 کاراکتر در SSH تنظیم می‌شود و باید جدا از فایل خارج از VPS نگهداری شود.

## بازیابی روی نصب موجود
مدیر اصلی مادر در منوی قبلی، فایل DELTA-FULL را ارسال می‌کند. سیستم فایل را بررسی می‌کند و یک دستور مشخص با هش همان فایل می‌دهد:
```bash
/usr/local/sbin/delta-full-backup apply SHA256_FROM_BOT
```
این دستور فقط برای root از SSH قابل اجراست، نه www-data. پس از بررسی مسیرها، تطبیق تنظیمات هدف، توقف نویسنده‌های شناخته‌شده، ساخت بکاپ ایمنی و تأیید هش، دیتابیس‌ها و مسیرهای عملیاتی موجود در بکاپ بازگردانده می‌شوند. تنظیمات MySQL و رمز root هدف عمداً جایگزین نمی‌شوند. سرویس‌های قبلاً فعال دوباره شروع می‌شوند؛ Apache configtest، اتصال دیتابیس و رمزگشایی پنل‌های اپ بررسی می‌شوند. اگر پس از آغاز جایگزینی خطا رخ دهد، نویسنده‌ها متوقف می‌مانند و فایل safety برای بازیابی دستی حفظ می‌شود. دیتابیس اضافه خارج از فهرست به صورت خودکار حذف نمی‌شود.

## سرور تازه / از دست رفتن سرور
1. Ubuntu 24.04، GitHub checkout همان نسخه مورد بررسی، python3 و gpg نصب شود. ابتدا بدون نصب ربات، helper را نصب کنید:
```bash
sudo bash scripts/install-full-backup.sh --recovery-only
```
همان رمز مستقل قدیمی را در SSH وارد کنید.
2. فایل رمزگذاری‌شده را امن منتقل کنید. اعتبارسنجی و استخراج تنظیمات قدیمی:
```bash
/usr/local/sbin/delta-full-backup verify-local < /root/DELTA-FULL.delta.gpg
/usr/local/sbin/delta-full-backup prepare-install SHA256_FROM_VERIFY
```
اطلاعات نصب در پوشه خصوصی root با mode 0600 قرار می‌گیرد؛ آنها را در چت یا GitHub منتشر نکنید.
3. با اطلاعات اصلی و دامنه و توکن و نام کاربر و رمز دیتابیس قبلی، ربات را روی نسخه سیستم‌عامل و وابستگی‌های سازگار نصب کنید. محیط VPSBot و ابزار rsync باید موجود باشند. مسیر DNS و SSL باید آماده باشد. نصب اولیه نباید در زمان آزمایش آزمایشی وب‌هوک واقعی را روی VPS دیگری جابه‌جا کند.
4. پس از بررسی ایزوله و تأیید مالک، دستور apply با همان هش اجرا شود؛ سپس helper را در حالت عادی نصب کنید تا منوی بکاپ مجدداً فعال شود. وب‌هوک‌ها، دریافت SMS، اتصال پسارگارد، پرداخت و خرید واقعی باید بررسی شوند.
5. در شرایط بازگردانی کامل و خطا، فایل before-restore را با verify-local بررسی و طبق دستور root بازیابی کنید؛ در صورت خرابی یا عدم تطبیق نصب هدف به بررسی دستی نیاز است.

## محدودیت‌ها
- Telegram Cloud Bot API: فایل بالاتر از 19 MiB روی سرور ذخیره می‌شود. برای آن همان فایل را خارج از تلگرام با انتقال امن و verify-local بازیابی کنید. محدودیت پیام‌رسان را دور نمی‌زنیم.
- بکاپ SQL بین دیتابیس‌ها یکپارچه است، اما فایل‌ها پس از dump گرفته می‌شوند؛ برای نقطه زمانی مشترک تضمین‌شده، بکاپ نهایی مهاجرت را در پنجره نگهداری انجام دهید.
- آزمون‌های CI شامل GPG، دستکاری فایل، رمز اشتباه، استخراج امن، تطبیق هدف و dump/restore MySQL هستند. آزمون واقعی کل سرویس‌ها و بازیابی روی VPS تازه هنوز لازم است. فقط پس از بازیابی موفق و نگهداری نسخه خارج از سرور ریبلد کنید.
