# بکاپ رمزگذاری‌شده کل مجموعه دلتا — پیش‌نمایش توسعه

این شاخه برای VPS اختصاصی botme با نام دیتابیس مادر delta طراحی شده است. هنوز مجوز ریبلد یا انتشار روی محیط اصلی نیست.

## محدوده
- یک dump با قفل سراسری از delta، تمام دیتابیس‌های موجود delta_rbN و delta_sms_bridge.
- اگر دیتابیس نمایندگی فعال مفقود باشد، بکاپ متوقف می‌شود.
- کل وب‌روت اختصاصی (شامل پنل و DeltaPay)، تنظیمات Apache/PHP/MySQL، SSL، Cron، سرویس‌های VPSBot، سورس عملیاتی و داده‌ها و تنظیمات SMS Bridge.
- بکاپ SQLite با API سازگار SQLite در صورت یافتن فایل واقعی در مسیرهای VPSBot. مسیر سفارشی خارج از این پوشه‌ها هنوز باید روی سرور واقعی بررسی شود.
- فهرست پکیج‌ها و manifest شامل اندازه و SHA-256 همه اجزای اصلی.
- سیستم‌عامل، دیسک پنل‌های VPN خارجی، احراز هویت GitHub، کلید امضای اپ روی سرویس جداگانه و فایل‌های خارج از مسیرهای مشخص‌شده جزو این بکاپ نیستند.

## امنیت
فایل DELTA-FULL-*.delta.gpg با GPG/AES256 و رمز مستقل مالک رمزگذاری می‌شود. رمز در Telegram یا GitHub قرار نمی‌گیرد. فایل ورودی ابتدا اعتبارسنجی می‌شود و هیچ SQL یا کد آرشیو در مرحله verify اجرا نمی‌شود.
تنها دو دستور ثابت create و verify به www-data مجاز است. بازگردانی سطح root به‌طور عمدی از ربات قابل اجرا نیست. فقط مدیر اصلی مادر امکان دریافت یا ارسال بکاپ کامل را دارد. بکاپ نمایندگی مستقل همچنان SQL همان دیتابیس است.
فایل بزرگ‌تر از 19 MiB روی سرور محفوظ می‌ماند و با روش امن باید خارج شود. هنوز انتقال خودکار فایل بزرگ از Telegram پشتیبانی نمی‌شود.
عکس‌برداری SQL بین دیتابیس‌ها یکپارچه است، اما گرفتن فایل‌های عملیاتی در زمان بعد از dump انجام می‌شود؛ برای تضمین نقطه بازیابی مشترک باید یک پنجره نگهداری تعریف شود.

## وضعیت بازیابی
فایل کامل دریافتی از همان منو با کلید مستقل و هش‌ها بررسی می‌شود و نسخه معتبر در /var/lib/delta-full-backup/verified-pending.tar.gz (فقط root) آماده می‌شود. این مرحله داده‌های فعال را تغییر نمی‌دهد. بازیابی خودکار همه دیتابیس‌ها/فایل‌ها، تطبیق حساب‌های MySQL در VPS تازه، بازگردانی سرویس‌ها و آزمایش خرید واقعی هنوز نیازمند تکمیل و تست بازیابی در VPS جداگانه است. بدون آن ریبلد نکنید.
