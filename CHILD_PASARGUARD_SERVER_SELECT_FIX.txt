Child/Reseller PasarGuard purchase-flow fix

Root cause:
- Child bots switch to a dedicated database after the main database migrations have already run.
- Their reseller template was missing newer PasarGuard columns.
- On PHP 8 / mysqli strict error mode, selecting a PasarGuard server could throw an
  unknown-column mysqli_sql_exception and terminate the callback.

Fixes:
- Run PasarGuard renewal, quota, server config and user approval migrations after
  switching to every child bot database.
- Track schema checks per database instead of once per PHP request.
- Update reseller_template.sql for newly-created bots.
- Harden renewal lookup helpers against incomplete older databases.
- Replace the server category N+1 queries with one joined query.
- Catch and log selection errors instead of letting the bot callback terminate.
